# 一个 8 KiB hive 的逐字节走查

下面所有字节都来自本机真实生成的文件：先用 `moon run cmd/main -- --build demo.hive` 生成，再用本库自己的 CLI 读回（`tree keys  : 3`、`checksum   : 0x667c754b`）。任何一步都能自己重跑对照，不需要 Windows。

文件总长 8192 字节：前 4096 字节是 base block，后面是一个 4096 字节的 hbin。

## 1. base block 的头部

```
0x0000  72 65 67 66 01 00 00 00 01 00 00 00 00 00 00 00  |regf............|
0x0010  00 00 00 00 01 00 00 00 05 00 00 00 00 00 00 00  |................|
0x0020  01 00 00 00 20 00 00 00 00 10 00 00 01 00 00 00  |.... ...........|
0x0030  52 00 4f 00 4f 00 54 00 00 00 00 00 00 00 00 00  |R.O.O.T.........|
```

| 偏移 | 观测值 | 含义 |
| --- | --- | --- |
| 0x00 | `72 65 67 66` | 签名 `regf` |
| 0x04 | 1 | 主序列号 |
| 0x08 | 1 | 次序列号 |
| 0x14 | 1 | 主版本 |
| 0x18 | 5 | 次版本 |
| 0x1C | 0 | 文件类型（0 主文件、1 旧日志、6 新日志） |
| 0x20 | 1 | 文件格式 |
| 0x24 | 32 | 根键 cell 偏移，相对 bins 起点 |
| 0x28 | 4096 | bins 数据长度 |
| 0x2C | 1 | 簇因子 |
| 0x30 | `ROOT` | 文件名，UTF-16LE 共 32 个码元；空表示未命名 |

## 2. 校验和只覆盖前 508 字节

```
0x01f0  00 00 00 00 00 00 00 00 00 00 00 00 4b 75 7c 66  |............Ku|f|
```

把 `0x00` 到 `0x1FB` 的 508 字节按小端 u32 读成 127 个数逐个异或，得到 `0x667c754b`；文件在 `0x1FC` 存的也是 `0x667c754b`，两者相等。

这条校验和只保护 base block 的前 508 字节：改写 `0x1FC` 之后的任何字节都不会让它失效。所以它只能发现头部损坏，不能发现结构错位——结构错位要靠偏移表加白盒用例守。

## 3. hbin 头

```
0x1000  68 62 69 6e 00 00 00 00 00 10 00 00 00 00 00 00  |hbin............|
0x1010  00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00  |................|
0x1020  a8 ff ff ff 6e 6b 2c 00 00 00 00 00 00 00 00 00  |....nk,.........|
```

| 偏移 | 观测值 | 含义 |
| --- | --- | --- |
| 0x1000 | `hbin` | hbin 签名 |
| 0x1004 | 0 | 相对第一个 hbin 的偏移 |
| 0x1008 | 4096 | 本 hbin 总长度，4096 的整数倍 |

## 4. 根键的 cell

base block 的 `0x24` 写着 32，加上 bins 起点 4096 得 `0x1020`。这里偏移指向 cell 长度字段（值 -88，负数表示已分配），紧接其后的 0x1024 起才是 nk 签名。

```
0x1020  a8 ff ff ff 6e 6b 2c 00 00 00 00 00 00 00 00 00  |....nk,.........|
0x1030  00 00 00 00 ff ff ff ff 01 00 00 00 00 00 00 00  |................|
0x1040  78 00 00 00 ff ff ff ff 00 00 00 00 ff ff ff ff  |x...............|
0x1050  ff ff ff ff ff ff ff ff 08 00 00 00 00 00 00 00  |................|
```

`0x1024` 处是 `nk`；键名、子键列表与值列表都在这个 cell 里，逐字段口径见 [DESIGN.md](../DESIGN.md) 的「REGF 字段偏移」一节。

## 5. 自己复核

```
moon run cmd/main -- --build demo.hive
moon run cmd/main -- demo.hive
moon run cmd/main -- demo.hive --values
```

Windows 上再用 `Format-Hex -Path demo.hive`、Linux 上用 `xxd demo.hive` 对照上面三段十六进制。同一棵键树重建会得到相同字节，所以这些数字可以原地复现。
